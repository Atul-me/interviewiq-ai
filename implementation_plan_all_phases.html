InterviewIQ AI

Master Implementation Plan & Architecture Specification (Phases 1–10)

🌐 Phase 1: Foundation & Project Scaffold

Establishes a robust, decoupled MERN infrastructure optimizing security configurations and logging systems.

Core Architecture

  • Security Middlewares: Enforces Express-level security with helmet security headers, cors validation controls, and express-rate-limit throttles.
  • Database connection: Singleton database module tracking events (connected, disconnected, error) with automatic error recovery layers.
  • Unified Winston logger: Decoupled logging formatting console output with custom levels (http, info, debug, warn, error) and pipe outputs to file logs.

Code Blueprint (db.js)

const mongoose = require('mongoose');
const connectDB = async () => {
  try {
    const conn = await mongoose.connect(process.env.MONGO_URI);
    console.log(`MongoDB Connected: ${conn.connection.host}`);
  } catch (err) {
    console.error(`Database connection failed: ${err.message}`);
    process.exit(1);
  }
};

🔐 Phase 2: Authentication Pipeline

Implements JWT-based user authentication using secure salting algorithms and Joi input validation schema guards.

Core Architecture

  • User Model: Mongoose pre-save hook automatically hashes passwords using bcryptjs with a work factor of 12.
  • Route Guards: Express protection middleware verifying Bearer tokens, decoding JWT signatures, and resolving database credentials.
  • Validation Middleware: Validates incoming request parameters against strict Joi schemas, blocking parameter pollution.

🎨 Phase 3: Frontend Scaffold & Core UI

Sets up a responsive, dark-mode React application powered by Vite, Tailwind CSS, global Context APIs, and Axios interceptors.

Core Architecture

  • Axios Client: Injects authentication tokens into headers automatically and intercepts expired session responses.
  • Auth & Toast Contexts: Handles state propagation for logged-in user profiles and coordinates dynamic popup alerts.
  • Route Protection guards: Enforces Protected and Public route constraints redirecting users based on login state.

📄 Phase 4: Resume Parsing Pipeline

Establishes Multer file upload pipelines, file format checks, and asynchronous PDF plain-text parser controllers.

Core Architecture

  • Storage Configuration: Restricts upload parameters to 5MB PDF-only files under uploads/resumes/.
  • pdf-parse Integration: Invokes class-based parsing constructors to pull raw text streams from file buffer arrays.
  • User Profile Update: Persists parsed resume text directly on the MongoDB user document for subsequent context tailoring.

🤖 Phase 5: Gemini AI Engine Integration

Enforces structured JSON response schemas directly from Google Gemini API endpoints without regex cleaning steps.

Core Architecture

  • Structured Output: Configures generationConfig parameters with responseMimeType: "application/json" and schema definitions.
  • Model Choice: Utilizes gemini-1.5-flash for fast, cost-efficient, and structured text generation.
  • Modular Prompt Engine: Builds dynamic interview tailoring systems that inject target roles, difficulty settings, and resume details.

📅 Phase 6: Mock Interview Session Management

Controls the full session lifecycle including starting sessions, answer inputs, real-time evaluations, and final scoring scorecard aggregation.

Core Architecture

  • Interview Collection Model: Persists the active interview state, nested question parameters, and scoring metrics.
  • Progressive Evaluation: Evaluates candidate answers sequentially as they are submitted, storing individual evaluations.
  • Aggregation Controller: Averages active session scores, appends overall feedback summaries, and seals document states on completion.

📊 Phase 7: Analytics Dashboard

Builds fast MongoDB aggregation pipelines evaluating candidate progress and category proficiencies.

Core Architecture

  • Aggregation Framework: Groups data dynamically inside MongoDB to optimize network overhead.
  • Proficiency Analysis: Evaluates question averages grouped by category to diagnose candidate strengths and weaknesses.
  • Timeline Progress: Sorts completed session logs chronologically for rendering progress charts.

🎙️ Phase 8: Advanced Features (Voice & Caching)

Implements audio answer recordings, speech-to-text translations via Gemini multimodal APIs, and response cache systems.

Core Architecture

  • Multimodal Transcription: Uploads audio recordings, converts binaries to inline base64 data, and requests Gemini transcriptions.
  • Volatile Caching layer: Exposes a caching service with TTL support that falls back gracefully to local memory maps when Redis is absent.
  • Cache Invalidation: Triggers automatic cache flushes whenever starting, grading, or completing interview sessions.

🛠️ Phase 9: Production Readiness & Optimization

Configures mono-repo start setups and production static files serving fallbacks directly inside Express routes.

Core Architecture

  • Orchestrated Tasks: Utilizes concurrently packages to run prefix build commands for both backend and frontend.
  • SPA Routing fallback: Serves pre-built client resources in production and maps non-API route requests to React's index template.

📄 Phase 10: Documentation & Handover

Presents a comprehensive platform specifications and setup handbook to final developers.

Core Deliverables

  • README.md Setup Guide: Describes folder structures, configurations variables, and local commands.
  • API Specification Sheets: Documents endpoint headers, payload formats, and expected JSON structures.
